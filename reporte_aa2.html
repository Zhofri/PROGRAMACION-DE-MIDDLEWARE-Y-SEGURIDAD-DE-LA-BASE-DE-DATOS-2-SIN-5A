1. Introducción

El presente informe detalla el proceso de desarrollo del "Aprendizaje Autónomo 2", el cual da continuidad al portal web del emprendimiento "Materials Fadrell". En esta segunda fase, el objetivo principal fue pasar de una página web estática a una aplicación dinámica, integrando un backend en Python (Flask) para procesar el formulario de contacto, almacenando la información en una base de datos MariaDB, enviando confirmaciones por correo electrónico y consumiendo una API externa (OpenWeatherMap) para proveer datos meteorológicos en tiempo real.

2. Paso 1: Tabla de Contacto E/R y Backend Python

Para cumplir con los requerimientos del formulario de contacto, se diseñó primero la estructura en la base de datos `materials_fadrell`. Se creó la tabla `contacto` con los campos necesarios (nombre, email, mensaje y fecha de registro).

CREATE TABLE IF NOT EXISTS contacto ( id INT AUTO_INCREMENT PRIMARY KEY, nombre VARCHAR(100) NOT NULL, email VARCHAR(150) NOT NULL, mensaje TEXT NOT NULL, fecha_registro TIMESTAMP DEFAULT CURRENT_TIMESTAMP ) ENGINE=InnoDB;

Para el procesamiento de los datos ingresados en el portal web (Frontend), se desarrolló una API utilizando el micro-framework Flask de Python. Este servidor se encarga de recibir las peticiones POST enviadas por JavaScript (mediante la función `fetch`). En el bloque de código de Flask, se utilizó la librería `pymysql` para insertar los datos en MariaDB. Se aplicó el manejo de excepciones con bloques `try/except` para garantizar que la aplicación no falle abruptamente si ocurre un error de conexión, tal como se revisó en clases.

Una vez que los datos se guardan exitosamente en la base de datos, el script en Python invoca la librería `smtplib` para enviar un correo electrónico automático de "acuse de recibo" al cliente, garantizando una excelente experiencia de usuario.

Adicionalmente, se construyó un script independiente llamado `subir_ftp.py` utilizando el módulo nativo `ftplib`. Este programa automatiza el proceso de empaquetar los códigos fuente en un archivo `.zip` y subirlo a un servidor FTP, agilizando el proceso de despliegue de la aplicación.

3. Paso 2: Reporteador de Clima (API REST)

Para el desarrollo de la sección meteorológica, se requería consumir datos en tiempo real. Esto es especialmente útil para un emprendimiento de materiales de construcción, ya que los contratistas pueden revisar el clima antes de planificar fundiciones de losas o despachos.

Se creó una cuenta en OpenWeatherMap y se generó una API Key personal. En la interfaz gráfica (HTML), se agregó la pestaña "CLIMA" a la barra de navegación principal. En el archivo `app.js`, se implementó la función `setupWeatherAPI()`, la cual realiza una petición HTTP GET al endpoint de OpenWeatherMap solicitando los datos de la ciudad de Loja, Ecuador, en unidades métricas.

function setupWeatherAPI() { const apiKey = 'eada7b6266bdf41847a33bd22948d455'; const city = 'Loja,EC'; const url = `https://api.openweathermap.org/data/2.5/weather?q=${city}&appid=${apiKey}&units=metric&lang=es`; fetch(url) .then(response => response.json()) .then(data => { // Se actualiza el DOM con jQuery $('#clima-temp').text(Math.round(data.main.temp) + '°C'); $('#clima-humedad').text(data.main.humidity + '%'); $('#clima-desc').text(data.weather[0].description); $('#clima-viento').text(data.wind.speed + ' m/s'); }) .catch(error => console.error(error)); }

Los datos recibidos en formato JSON (Temperatura, Humedad, Descripción y Velocidad del Viento) son procesados por JavaScript e inyectados dinámicamente en el DOM utilizando jQuery. Además, se incluyó la obtención del ícono dinámico provisto por la misma API para mejorar la presentación visual.

4. Conclusiones

El desarrollo de esta segunda fase del proyecto demuestra la importancia de integrar múltiples tecnologías (Frontend, Backend, Bases de Datos y APIs de terceros) para construir aplicaciones web funcionales y robustas. El uso de Flask junto con `pymysql` permitió establecer una comunicación eficiente y segura con la base de datos MariaDB, aislando la lógica de negocio y las credenciales del lado del cliente. Por otro lado, la incorporación de notificaciones por correo (`smtplib`) y el consumo de APIs externas (OpenWeatherMap) elevan el nivel del proyecto, ofreciendo funcionalidades modernas que aportan un valor real al usuario final.

Finalmente, el uso de herramientas como Git (GitLab) y FTP automatizado asegura un control de versiones adecuado y facilita el despliegue de los entregables, cumpliendo con los estándares de desarrollo enseñados en la asignatura.
